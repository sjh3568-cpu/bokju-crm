# 복주 상담실 CRM — 사용 매뉴얼

> 신규 상담사 온보딩 / 일상 업무 참고용. **메뉴별 역할 + 활용 시나리오 + 메뉴 간 연계도**.

---

## 8개 메뉴 한 줄 요약

| 메뉴 | 한 줄 |
|---|---|
| 🏠 대시보드 | 5초 만에 보는 우리 팀 컨디션 |
| 📥 인박스 | 오늘 처리해야 할 To-Do |
| ✍️ 새 상담 | 통화 끝나고 한 화면에 다 채워서 저장 |
| 📋 상담 목록 | 과거 상담 검색용 백과사전 |
| 🚶 생애주기 | 환자별 여정 지도 |
| 💬 문자 | 환자군별 정형 문구로 1-click 발송 |
| 📊 통계 | 자유 기간 깊은 분석 차트 |
| 📈 월간보고서 | 임원 회의용 A4 1페이지 자동 보고서 |

## 🏠 대시보드 (`/`)

**"오늘 아침 출근해서 첫 번째로 보는 화면. 5초 만에 우리 팀 컨디션 파악."**

### 화면 구성
- 이번 달 카드 4장 — 총 상담 / 입원예정 등록 / 비율 / 30일 이내 퇴원예정
- 오늘 등록된 상담 — 시각·환자·주치의·호실·입원예정일 (행 클릭 → 상담 상세)
- 최근 7일 상담 추이 — 미니 라인 차트

### 활용 시나리오
1. 출근 직후 → "이번 달 우리 어디까지 왔지?" 컨디션 체크
2. 오전 회의 전 → "오늘 어떤 환자 상담이 들어왔지?" 빠른 확인
3. 30일 이내 퇴원예정 카드 클릭 → 입원완료 환자 목록으로 이동

### 다른 메뉴와의 차이
- **인박스**가 "오늘 할 일"이면, 대시보드는 "**우리 팀 전반 컨디션**".
- 통계와 달리 오늘+이번 달에 집중 — 빠른 상태 확인용.

## 📥 인박스 (`/inbox`)

**"이메일의 받은편지함처럼, 오늘 처리해야 할 일을 채널 무관 한곳에 모은 화면."**

### 4개 섹션이 답하는 질문

#### 📞 재연락 대기
- **질문**: "전에 통화하다가 '나중에 다시 연락드릴게요'라고 약속한 건 누구였지?"
- **언제 뜨나**: 상담일지에서 상담 결과를 `상담요청`으로 표시한 건
- **여기서 하는 일**: 보호자 연락처·재연락 사유 보고 [문자]·[상담]으로 후속 처리. 1-click 완료 마킹도 가능
- **사라지는 순간**: 상담 결과를 `상담완료`/`상담취소` 등으로 변경

#### 📨 미처리 인바운드 (옴니채널)
- **질문**: "카톡 문의·웹문의·부재중 전화 중 답신 안 한 게 뭐지?"
- **언제 뜨나**: 카카오 webhook이나 직접 등록한 인바운드 메시지(`status='open'`)
- **여기서 하는 일**:
  - [상담 등록] — 새 상담일지 폼이 보호자 연락처·메시지까지 자동 채워진 상태로 열림. 저장 시 인박스 자동 제거 + 상담에 영구 연결
  - [처리완료] — 단순 안부 등 상담 등록 없이 확인 마킹
  - [삭제] — 스팸/오발신
- **블랙리스트 환자**일 경우 ⚠ 사전 표시

#### 🏥 입원 안내 예정 (D-3 이내)
- **질문**: "내일·모레 입원 예정 환자 가족에게 안내 문자 보내야 하는 사람 누구지?"
- **언제 뜨나**: `planned_admission_date`가 오늘부터 3일 이내인 상담
- **여기서 하는 일**: [입원안내 문자] 클릭 → 문자 페이지로 이동 (토큰 자동 치환)

#### 🚪 퇴원 예정
- **질문**: "입원 만료일 가까운 환자, 가족에게 미리 안내해야 하는데 누구지?"
- **언제 뜨나**: 입원완료된 환자 중 의료법 입원 기간 룰로 계산한 입원 만료일이 30일 이내
- 빨간 글씨 "**N일 초과**" — 이미 만료된 환자(연장 결정 필요)

### 활용 시나리오 (하루 흐름)
1. 출근하자마자 인박스 열기 — 어제 저녁~오늘 아침 들어온 카톡 문의·재연락 약속 한눈에 파악
2. 재연락 대기 처리 — 보호자 전화 돌리고 결과 업데이트
3. 미처리 인바운드 처리 — 신규는 [상담 등록]으로 정식 상담 생성
4. D-3 입원 안내 발송 — [입원안내 문자] 1-click
5. 퇴원 예정 사전 안내 — 만료 30일 전부터 가족에게 미리

### 인박스가 텅 비어 있으면 = 좋은 신호
미처리 0건 = 응대 잘 되고 있다는 뜻.

## ✍️ 새 상담 (`/consult/new`)

**"종이 상담일지의 디지털 버전. 통화 끝나자마자 한 화면에 다 채우고 저장하면 끝."**

### 폼 8개 섹션
1. **헤더** — 입원예정일·주치의(IM1 정기천/IM2 신현범/NE 변현숙/RM1 이성범/RM2 이석태)·호실·상담일자·시각·상담자(박세연/권창영/김미화/신재희)
2. **환자 기본정보** — 환자명(자동완성)·성별·나이·주소(시군구→시도 자동)·블랙리스트
3. **보호자** — 이름·관계·연락처(010- 자동 + 8자리 → 010-XXXX-XXXX)
4. **상담 방법·입원 경로** — 라디오/체크박스
5. **병명 4그룹** — 기저질환·중추신경계·근골격계·비사용증후군 (다중 체크 + 회복기 자동 판정)
6. **환자 상태** — 의식·활동·식이·상처·치료 등 다중 체크
7. **입원 확인** — 서류 체크리스트·이송 방법·비용 안내
8. **상담 결과** (2단계 분리)
   - ① 상담 진행: 상담완료/재입원 상담/상담요청/상담보류/상담취소
   - ② 입원 진행: 입원보류/입원취소/입원완료 (빈값=미정)

### 회복기 자동 판정 룰 (의료법 재활의료기관 본지정 기준)
- 중추신경계(뇌출혈/뇌경색/척수손상/마비): 발병 후 **90일** 이내
- 골유합 지연: **60일** 이내
- 근골격계(고관절/대퇴/골반/절단): 수술 후 **30일** 이내
- 비사용증후군(호흡/심장/CRE/VRE/패혈증/신생물/파킨슨(신규)/길랑바레): **60일** 이내
- 여러 병명 시 가장 긴 인정 기간 적용

### 입력 편의 기능
- 환자명 자동완성 — 기존 환자 매칭 시 보호자 정보·주소 자동 채움
- 시군구 입력 → 시도 자동 채움
- 발병일 — 날짜 선택기 + "정확한 날짜 모름" 체크 시 자유 텍스트
- 자주 쓰는 모병원 Top 5 빠른 선택 버튼
- 인박스에서 진입 시 보호자 연락처·메시지 자동 prefill + 노란 안내 배너

### 활용 시나리오
1. 보호자와 통화 → 옆에서 폼 열어두고 체크 → 통화 끝나면 저장
2. 인박스에서 진입 → 자동 채워진 정보 확인 + 빠진 부분만 입력
3. 재상담 시 → 환자명 자동완성으로 기존 환자 매칭 → N번째 상담 기록

## 📋 상담 목록 (`/consultations`)

**"검색용 백과사전. 과거 어떤 상담이 있었는지 필터·정렬해서 찾는 곳."**

### 화면 구성
- **필터바 10종** — 기간·상담자·거주도·병명그룹·유입경로·상담방법·회복기·상담결과·입원진행·검색어
- **테이블 13컬럼** — 상담일·환자(나이·성별)·블랙리스트·보험·결과·입원진행·주치의·호실·입원예정·상담자
  - 회복기 배지 (회복기/비회복기/일반재활), 임박 마크 (↓7일 빨강 깜빡임)
  - 동명이인 ⚠ 마크, 재상담 (#N) 마크
- **헤더 클릭 정렬** (7개 컬럼)
- **페이지네이션** — 100건/페이지
- **CSV 다운로드** (관리자만, 25컬럼)
- **일괄 작업** — 체크박스로 여러 건 선택 후 상태 일괄 변경·삭제

### 활용 시나리오
1. "지난달 ○○병원에서 온 입원완료 환자만 보고싶다" — 기간 + 모병원 + 입원진행 필터
2. "○○ 환자 다시 전화왔다 — 이전 상담 내역 확인" — 검색어 입력 → 행 클릭
3. 월말 보고용 — 모든 상담 CSV 다운로드 → 엑셀에서 추가 분석
4. 입원취소 환자 일괄 사유 라벨링

### 다른 메뉴와의 차이
- 인박스가 "오늘 액션 필요한 건"이라면 상담 목록은 "**모든 과거 상담 검색**"
- 통계가 "숫자·차트"라면 상담 목록은 "**개별 행 단위**"

## 🚶 생애주기 (`/lifecycle` + `/patients/<id>`)

**"환자 한 명 한 명의 여정 지도. 지금 어느 단계에 있고, 다음에 뭘 해야 하는지."**

### 보드 (`/lifecycle`) — Kanban 7개 컬럼
```
상담 → 입원대기 → 입원 → 응급치료 → 회복기 → 비회복기 → 퇴원
```
- 각 카드: 환자명·나이·성별·병명·최근 상담·상담수·이벤트수·단계 드롭다운·[기록 ›] 링크
- 검색바로 환자명·연락처 검색
- 단계가 지정된 환자만 표시 (opt-in)

### 환자 상세 (`/patients/<id>`)
- 기본정보 + 블랙리스트 토글 + 생애주기 단계 드롭다운
- **통합 타임라인** — 상담·문자·생애주기 이벤트·커뮤니케이션 4개 소스를 시간순 병합
- **생애주기 이벤트 추가 폼** — 응급치료/복귀/회복기·비회복기 전환/보호자·환자 요구사항/퇴원 등
- 커뮤니케이션 기록 폼 (전화·문자·카톡 부재중 등 수동 기록)
- 상담 이력 테이블

### 자동 전진
- 입원완료 → 입원 단계 자동
- 입원보류 → 입원대기 단계 자동
- 퇴원완료 → 퇴원 단계 자동
- (후진은 없음, 수동으로만 가능)

### 활용 시나리오
1. 회의실 화면에 띄워두고 — "이번 주 응급치료 받은 환자 있나?" 컬럼 한눈에 보기
2. 환자 상세 타임라인 — "이 환자 지난번에 보호자가 뭐라고 했더라?" 한눈에 시간순
3. 응급치료·복귀 이벤트 → 임원 보고에 활용

### 다른 메뉴와의 차이
- 상담 목록은 **상담(이벤트) 단위**, 생애주기는 **환자(주체) 단위**
- 같은 환자의 N번째 상담들이 한 페이지에 시간순으로 모임

## 💬 문자 (`/sms` + `/sms/templates`)

**"환자군별 정형 문구를 토큰 치환해서 발송. 인박스에서 1-click 연결."**

### 발송 화면 (`/sms`)
- 수신자 선택 — 최근 상담 200건 드롭다운 (`?cid=N`으로 인박스에서 자동 선택)
- 환자군별 템플릿 버튼 — 입원안내·퇴원안내·재연락 등
- 본문 textarea — 토큰 자동 치환: `{환자명}` `{보호자명}` `{병원명}` `{입원예정일}` `{주치의}`
- 전송 이력 테이블 — 최근 발송 내역

### 템플릿 관리 (`/sms/templates`)
- 환자군별 정형 문구 등록·수정·삭제

### 현재 한계
- 발송사 미정 → 현재 'manual' 모드 → 휴대폰 문자앱 `sms:` 링크 클릭으로 본인 휴대폰에서 발송
- 발송사 결정 시 `.env`에 `SMS_API_KEY`/`SMS_SENDER` + `sms.send_sms()` 구현하면 자동 발송

### 활용 시나리오
1. 인박스 D-3 입원안내 → [입원안내 문자] 1-click → 토큰 치환된 본문 자동 작성
2. 재연락 약속한 환자에게 약속 시간 전 안내
3. 퇴원 임박 환자에게 사전 안내

### 다른 메뉴와의 차이
- 다른 메뉴는 "조회·기록"이지만 문자는 "**발송 액션**"
- 발송 결과는 `sms_log` → 환자 상세 타임라인에 자동 반영

## 📊 통계 (`/stats`)

**"숫자와 차트로 보는 우리 팀 성적. 기간 선택해서 어떤 채널이 잘 되는지 분석."**

### 화면 구성
- 기간 선택 — 이번달·지난달·이번분기·지난분기·올해·직접지정
- 상단 KPI 6+1장 — 총 상담·입원완료·전환율·입원보류·입원취소·일평균·최다 입원경로/거주지/병명
- **12+ 차트** (Chart.js v4 + datalabels):
  - 시계열 라인 (일별 추이)
  - 도넛 5종 (입원경로 그룹·병명 그룹·보험·상담방법·성별)
  - 수평 막대 4종 (입원경로 세부·병명 Top15·시도·시군구 Top10)
  - 수직 막대 2종 (연령대·상담자별)
- **Claude AI 인사이트 버튼** (ANTHROPIC_API_KEY 있을 때만, 환자 식별정보 미전달)

### 활용 시나리오
1. 분기 회의 전 — 분기 선택 → 어떤 채널이 입원완료로 잘 가는지 확인
2. KPI 카드 + 병명 그룹 도넛으로 "최근 비사용증후군 환자 늘었나?" 확인
3. 상담자별 막대 차트 — 누가 얼마나 응대했는지 (업무 분배 참고용)
4. Claude 인사이트 — 자연어로 "이번 분기 특이점 3가지" 자동 요약

### 다른 메뉴와의 차이

## 보안 원칙 (의료기관 — 절대 준수)

- 사내망 한정 (`127.0.0.1` 또는 사내 서브넷). 외부 인터넷 노출 금지
- 외부 클라우드 DB·호스팅 절대 금지
- 외부 API 호출은 처리 목적 한정 (Claude, CLOVA STT). 환자 식별정보 최소화
- 세션 4시간 자동 로그아웃, 5회 실패 시 5분 잠금
- 감사 로그 — login, view_consult, view_patient, create/update_consult, export 모두 기록
