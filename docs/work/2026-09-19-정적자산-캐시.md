## ① 무엇을  — `plan`

**배경**

화면을 넘길 때마다 같은 css·js를 **통째로 다시 받는다.** `app.py` 의 `_no_store` 훅이
`/static/*` 응답에도 `no-store` 를 걸기 때문이다.

원래는 "폰트가 PC마다 달라 보인다"를 보려던 작업이었는데, 확인해 보니 CDN이 막혀 있지 않아
폰트는 정상이었다(사용자 확인 2026-09-19). 그 과정에서 이 문제가 나왔다.

실측 근거 (테스트 클라이언트로 직접 확인):

```
GET /static/css/style.css  →  200  Cache-Control: no-store, private, must-revalidate
                                   Content-Encoding: (없음)   ← 압축도 안 됨
                                   ETag: 있음,  Last-Modified: 있음
```

- 정적 파일은 `send_file` 의 `direct_passthrough` 라 `_gzip_response` 가 건너뛴다 → **압축 없이 전송**
- 대시보드 1회가 받는 양:
  `style.css 93KB + dashboard.css 44KB + form.js 69KB + chart.umd.min.js 201KB + 외 13KB` = **420KB**
- 그런데 `ETag`·`Last-Modified` 는 **이미 붙어 있다** → 재검증만 허용하면 304로 끝난다

이 프로젝트는 대시보드를 299→119ms로 줄이려고 지연 로딩·gzip까지 넣었는데
(`docs/HISTORY.md` 2026-09-15), 매 화면 420KB를 그냥 버리고 있었다.

**하려는 것**

`_no_store` 에서 **정적 자산만** `Cache-Control: no-cache` 로 바꾼다.

| | 뜻 | 결과 |
|---|---|---|
| `no-store` (지금) | 저장 금지 | 매번 420KB 전체 전송 |
| `no-cache` (바꾼 뒤) | 저장하되 **쓰기 전 재검증** | 안 바뀌었으면 **304, 본문 0바이트** |

배포로 파일이 바뀌면 `ETag` 가 달라져 **즉시** 새로 받는다. 오래된 css가 남는 일이 없다.
정적 자산(css·js·이미지)에는 환자 정보가 없으므로 보안 원칙에 저촉되지 않는다.

**안 할 것**

- **`max-age` 를 길게 주기** — 배포 후에도 옛 css가 상담사 브라우저에 남는다.
  파일명 버전(`?v=`) 없이는 위험하다. `no-cache` 는 그 위험이 없다.
- **`url_for` 에 `?v=APP_VERSION` 붙이기** — 템플릿 53개를 건드려야 한다. 이번 범위 밖.
- **정적 파일 gzip 켜기** — `direct_passthrough` 를 풀어야 해서 파일 전송 동작이 바뀐다.
  304가 되면 애초에 본문이 안 나가니 효과가 겹친다. 필요하면 별건으로.
- **폰트를 저장소로 옮기기** — CDN이 정상이라 급하지 않다. 별건.
- **월간보고서 `Chart.js` CDN** (`report_monthly.html:4`) — `stats.html` 은 저장소 파일을 쓰는데
  여기만 CDN이다. 확인해 볼 값어치는 있지만 이번 건과 별개.

**할 일**

- [ ] `app.py` 의 `_no_store` 에 정적 자산 분기를 넣는다 (`request.endpoint == "static"`)
- [ ] ⚠ **환자 정보 화면의 `no-store` 가 그대로인지 반드시 확인** — 로그아웃 후 뒤로가기 노출 방지가
      이 훅의 원래 목적이다
- [ ] 회귀 테스트 추가 — 정적=`no-cache` / 화면=`no-store` / 재요청 시 304
- [ ] 실제 전송량이 줄었는지 확인

**확인 필요**

없음 — 범위가 좁고 되돌리기 쉽다(한 함수).

## ② 어떻게 만들었나  — 본인

**고친 파일**

- `app.py` `_no_store()` — 정적 자산 분기 11줄 추가 (그 외 파일 없음)

```python
if request.endpoint == "static":
    resp.headers["Cache-Control"] = "no-cache"
    resp.headers.pop("Pragma", None)
    return _gzip_response(resp)
```

**판단한 것**

- `request.endpoint == "static"` 으로 골랐다. 경로 문자열(`/static/`)로 보지 않은 이유는
  Blueprint가 늘어도 앱 전역 정적 라우트만 정확히 가리키기 때문. 확인 결과 현재 Blueprint 11개 중
  `static_folder` 를 가진 것은 없다.
- `Pragma` 를 지운다. HTTP/1.0 잔재라 남겨 두면 `no-cache` 와 뒤섞여 브라우저가 보수적으로 동작한다.
- **`max-age` 를 주지 않았다.** 주면 배포 후에도 옛 css가 상담사 브라우저에 남는다.
  `no-cache` 는 매번 재검증하므로 배포 즉시 반영되고, 안 바뀌었으면 304로 끝난다.
  이 프로젝트는 배포가 잦아서(`release.sh` → NAS) 신선도 쪽이 중요하다.
- `_gzip_response` 는 그대로 통과시킨다. 정적 파일은 `direct_passthrough` 라 어차피 건너뛴다.
