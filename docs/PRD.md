# 복주 상담실 CRM — PRD (제품 요구사항 정의서)

- 문서 버전: 1.0 (2026-09-10 현재 구현 기준 역작성)
- 대상 제품: bokju-crm v1.3.2
- 작성: 미래전략실 신재희

---

## 1. 제품 개요

### 1.1 미션
**세계 어느 병원의 상담관리 프로그램보다 쉽고 편리하게.**

복주회복병원 상담실 상담사가 **편리하게 기입**하고 **편리하게 통계·결과·관리**할 수 있도록,
통화 → 텍스트화 → 양식 자동 채움 → 통계·인사이트까지를 한 흐름으로 잇는 자체 구축 CRM.

### 1.2 사업적 근거
외부 상담관리 솔루션(나스카랩 등) 도입 대신 자체 구축으로
**5년 약 2,500만원 절감 + 병원 실무에 정확히 맞는 기능 확보**.

### 1.3 운영 컨텍스트
| 항목 | 내용 |
|---|---|
| 운영 주체 | 인덕의료재단 — 복주회복병원(재활) / 요양병원 / 요양원 |
| 현 적용 범위 | 복주회복병원 상담실 |
| 사용자 규모 | 상담사 4명(박세연·권창영·김미화·신재희) + 어드민/조회 계정 |
| 업무량 | 1일 상담 10–20건, 평균 통화 15분 |
| 병원 특성 | **입원 전용 재활병원 — 외래 환자 없음** |
| 전화 환경 | LG 헬로비전 IP폰 4대 (녹음은 현재 수동 다운로드) |
| 인프라 | 시놀로지 NAS(DS720+) 사내망, 병원 공식 카카오 비즈채널 보유 |

## 2. 문제 정의

기존 업무는 **종이 상담일지 + 구글시트/엑셀 마스터** 이원 관리였다.

1. **입력 이중화** — 통화 중 종이에 적고, 나중에 엑셀에 다시 옮긴다.
2. **통계 불가** — 시트가 연도·담당자별로 쪼개져 전환율·유입경로 ROI를 뽑을 수 없다.
3. **환자 이력 단절** — 재입원 환자의 과거 상담 이력을 사람의 기억에 의존한다.
4. **입원 진행 추적 부재** — 상담 후 실제 입원까지의 진행 상태(보류/취소/완료)가 남지 않는다.
5. **접점 분산** — 전화·문자·카카오·홈페이지 문의가 각각 다른 곳에 쌓인다.
6. **파일 공유의 한계** — SMB 공유폴더의 파일을 여러 PC가 동시에 열면 손상 위험.

## 3. 사용자와 목표

| 페르소나 | 핵심 요구 | 성공 기준 |
|---|---|---|
| **상담사 (4명)** | 통화하면서 끊기지 않고 입력, 재입원 환자 즉시 식별 | 통화 종료와 동시에 상담일지 완료 |

| **어드민** | 계정·권한·감사·백업 통제 | 메뉴별 권한 매트릭스로 관리 |

## 4. 범위

### 4.1 In Scope
- 상담일지 디지털화 (종이 양식·엑셀 마스터와 1:1 매칭)
- 환자 마스터 및 생애주기 추적
- 입원 진행 워크플로 (상담 결과 → 입원 진행 → 재원 → 퇴원)
- 재원 환자 관리 (외진·병실·연장·퇴원 예정)
- 통계·월간보고서 (AI 요약 포함)
- 문자 발송 및 템플릿
- 기관협력(협력병원) 관리
- 옴니채널 인바운드 (카카오·홈페이지 문의)
- 계정별 메뉴 권한, 감사 로그, 자동 백업
- 업무 보조 도구 (할 일/공유 달력, KRPG 조회, 회복기 기간 계산기)

### 4.2 Out of Scope (절대 금지)
- ❌ **외래 기능**(예약/NO SHOW/HappyCall/ARS 진료안내) — 입원 전용 병원
- ❌ 환자 개인정보의 외부 클라우드·SaaS 전송
- ❌ 외부 노출 호스팅(Vercel/Heroku/Render 등), 외부 클라우드 DB(RDS/Atlas 등)
- ❌ 종이 양식·엑셀 마스터에 없는 임의 필드 추가
- ❌ 마스터에 없는 모병원/추천기관 자유 텍스트 저장 (통계 분산 방지)
- ❌ 모병원 주소를 환자 거주지로 자동 채우기 (데이터 오염)
- ❌ 의료법 위반 표현(효과 단정·완치 보장)

## 5. 기능 요구사항 (현재 구현 완료)

메뉴 8종(`config.MENUS`) 기준.

### 5.1 대시보드 `/`
- 이번 달 KPI 카드 + 오늘 등록 + 7일 추이
- **개인 브리핑** — 내 입원예정 환자·내 재연락·내 할 일 (드릴다운 지원)
- **통합 달력** — 상담/입퇴원/공유 일정 + 음력 + 법정공휴일(대체공휴일 포함), 날짜 클릭 즉시 일정 등록
- **미처리 인바운드 카드**(`/#inbound`) — 카카오·홈페이지 문의 처리 창구
- 입원 현황 기간 조회

### 5.2 상담 `/consult/new`, `/consultations`, `/consult/<id>`
- **8개 섹션 폼** — 헤더 / 유입경로 / 환자상태 / 병명 4그룹 / 처치 / 입원확인 / 상담 결과 / 상세 메모
- **병명 4그룹** — 기저질환 · 중추신경계 · 근골격계 · 비사용증후군 (체크박스 + 상세 수기)
- **상담 결과 2단계 분리**
  - ① 상담 진행 `consult_result` 5종(상담완료/재입원 상담/상담요청/상담보류/상담취소) — 완료 외에는 사유 필수
  - ② 입원 진행 `admission_status`(입원보류/입원취소/입원완료, 빈값=미정) — 보류·취소 사유 필수
  - 입원취소 사유는 `REJECTION_REASONS` 8종 + 자유메모
- **입력 편의** — 환자명/병원/진단명 자동완성, 010- 자동 포맷, 시군구→시도 자동, 콤보박스, 날짜 요일 태그, 빠른 기간 프리셋
- **AI 자동 채움** — 통화 메모를 붙여넣으면 Claude가 상담일지 전 항목(병명 체크박스·환자 상태·발병일·모병원/추천기관 마스터 대조 포함)을 제안
- **임시저장(드래프트)** — 작성 중 이탈해도 복원
- **블랙리스트 안전장치** — 동일 이름·연락처가 블랙리스트면 저장 직전 확인 모달
- 목록 — 성별·나이·보험유형 개별 컬럼, 저장형 빠른 필터, CSV 내보내기, 인라인 상태 변경, 상담일지 인쇄
- 상세 — 환자 생애주기 타임라인, 입원 중 이벤트, 퇴원/연장 처리

### 5.3 재원 관리 `/ward`
- 3섹션 — **외진 중 · 재원 환자 · 입원일 미확정**
- **입원일 확정**(`POST /api/consult/<id>/admit`) 시점부터 재원 명부 + D-day 시작
- KPI 카드 클릭 → 해당 조건으로 목록 필터
- 입원 연장 분류(1년 → 1.5년 → 2년), 회복기 종료일, 주/부 진단, 내성균 표기
- 병상 입원대기 관리, 병실 배정, 관리 태그(이사장 소개 등), 5인실 자동
- 외진 出/歸 페어링 — 외진 중에는 퇴원 처리 거부
- 퇴원 후속 — 회복콜 · 퇴원 문자 · 퇴원 인터뷰
- 상세 필터 접기 + CSV

### 5.4 기관협력 `/partners`
- 심평원 명부(2026.3 기준 39,490곳: 의원·병원·종합병원·상급종합) 기반 기관 검색·연결
- 협력 담당자, 방문·연락 이력, 다음 일정(7일 전~기한 초과 표시)
- **협력기관 후보 자동 제시** + 실적/방치 표시, 명부 미연결 경고·수동 연결
- 기관별 기간 조회 — 상담은 상담일, 입원은 **실제 입원일** 기준, 환자+입원일로 중복 제거
- 업무협약서 메타데이터 관리(문서 파일 자체는 DB에 저장하지 않음)
- 공식 상세정보(진료과목·입원 병상 합계·간호간병통합 KH)를 기관코드로 연결해 수동 입력과 병행 표시

### 5.5 문자 `/sms`, `/sms/templates`
- 환자군별 템플릿 + 토큰 치환({환자명}{보호자명}{병원명}{입원예정일}{주치의})
- 발송 이력(`sms_log`) 기록
- **현재 한계** — 발송사 미정으로 `manual` 모드(휴대폰 문자앱 `sms:` 링크). 게이트웨이 자리만 구축

### 5.6 통계 `/stats`, `/stats/hospitals`
- 상단 KPI 6장 — 총 상담 / 입원완료 / 전환율 / 보류 / 취소 / 일평균
- 12종 이상 차트(Chart.js v4) + Claude 인사이트
- **모병원 분석** — 전체 순위표·병원명 검색, 표기 변형 통합, 기관연계/직접 방문 구분, 비기관 값 제외
- 문자 발송 현황 차트

### 5.7 월간보고서 `/report/monthly`
- KPI 8장(전월 대비 ±%) + 채널 ROI 표 + 모병원 Top 10 + 입원취소 사유 Top + 환자 포트폴리오 도넛 3종
- Claude 임원 요약 1단락 자동 생성
- `@media print` — **A4 1장** 인쇄 최적화

### 5.8 사용자 관리 `/admin/users` · 이력 관리 `/admin/audit`
- 계정 추가·비밀번호·역할·**메뉴별 권한**·활성/삭제
- 비밀번호 초기화 요청 및 관리자 알림, 권한 요청 처리
- 감사 로그 열람·필터·CSV (누가 언제 무엇을 조회/입력/수정/삭제)
- 백업 즉시 실행·검증 API

### 5.10 옴니채널 (인바운드)

## 6. 권한 모델

- **단계형 레벨** — 미현시(0) < 조회(1) < 수정(2) < 등록(3), 상위가 하위를 포함
- **메뉴 8종 × 계정별 레벨** = `users.permissions` JSON 매트릭스
- 조회 전용 메뉴(대시보드·통계·월간보고서)는 최대 레벨이 '조회'
- **역할(admin/staff/viewer)은 프리셋 이름일 뿐** — 생성 시 기본값을 채우고 이후 메뉴별로 조정
- `admin`은 비번 분실 대비 **break-glass 계정** — 항상 전권, 화면에서 편집 불가
- 안전장치 — 사용자 관리 권한 계정을 최소 1개 유지(마지막 1개 삭제·강등·비활성 금지)
- UI 레벨에서도 권한 없는 쓰기 버튼을 CSS로 숨김

## 7. 비기능 요구사항

### 7.1 보안 (의료기관 — 절대 준수)
- **사내망 한정**. 외부 인터넷 노출 금지. 외부로 여는 것은 `/api/webhook/*` 한 경로뿐
- 외부 API 호출은 처리 목적 한정(Claude 등), 환자 식별 정보 최소화
- 비밀번호 해시(werkzeug), 세션 4시간 자동 로그아웃, 5회 실패 시 5분 잠금
- 응답 헤더 `Cache-Control: no-store, private` (뒤로가기 노출 방지)
- 감사 로그 — login, view_consult, view_patient, create/update_consult, export
- 환자 식별정보를 로그·텔레메트리에 평문 출력 금지

### 7.2 가용성·데이터 보호
- 자동 백업 — 기동 시 1회 + 매일 03시, 30일 보관, SQLite 온라인 백업 API(무중단)
- 엑셀 import 직전 자동 백업
- 컨테이너 `restart: unless-stopped` + 헬스체크(60초 간격)
- **DB는 반드시 로컬 파일시스템** — SMB 공유폴더에 두면 WAL이 깨져 데이터 손상

### 7.3 성능
- 동시 사용자 4명 규모 기준. waitress 8스레드, SQLite WAL
- 실측 데이터 상담 8,028건 / 환자 7,665명에서 목록·통계 응답 정상

### 7.4 사용성
- 종이 상담일지 + 엑셀 마스터 양쪽에 1:1 매칭되는 폼 배치
- 한 줄 안에서 끊기지 않는 입력칸(`flex-shrink:0`, 라벨 `nowrap`)
- 카테고리별 시각 박스(`option-group`/`opt-box`), 남은 공간 자동 분배(`dx-stretch`)
