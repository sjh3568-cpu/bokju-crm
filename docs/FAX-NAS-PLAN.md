# 팩스 수신 자료 NAS 저장 — 다음 업무 PC 설정 메모

2026-09-09 사용자와 협의. 다음 업무일에 상담실 업무용 PC에서 설정을 이어간다.

## 결정한 방향

- 복합기: 삼성 SL-M2870FW (사용자 사진으로 확인).
- 상담사 PC마다 USB 케이블을 연결하기 어려우므로 사내 Wi-Fi 또는 유선 네트워크 연결을 우선 검토한다.
- 최종 팩스 PDF 저장 위치는 NAS 공유폴더로 한다.
- 현재 구상: 복합기 → 수신 담당 Windows PC 한 대 → NAS 공유폴더 → CRM 원본 조회·AI 정리.
- 담당 PC 로컬 폴더에 우선 수신하고 NAS로 자동 복사하는 방식을 검토한다. NAS 장애 시 로컬 보관·재전송·중복 방지·복사 완료 확인을 구현할 필요가 있다.
- 종이 출력도 유지하려는 요구가 있다. Easy Printer Manager의 수신 팩스 인쇄 옵션을 확인하고 시험 팩스로 PDF 저장과 출력 병행을 검증한다.
- 향후 CRM 프로그램도 NAS에서 실행하고 데이터도 NAS 내부에 저장할 계획이다. SQLite DB를 PC에서 SMB 공유 경로로 직접 열지 않고 NAS 내부 파일시스템에서 서버가 접근하도록 한다.
- AI 자료함과 자동 복사는 아직 구현하지 않았다. 이번 협의는 방향 결정이며 실제 장비 설정은 아직 하지 않았다.

## 확인된 기능과 제한

- SL-M2870FW는 PC 팩스 수신을 지원한다.
- 이 모델의 PC 없는 NAS 직접 저장 기능은 확인되지 않았다. 지원한다고 단정하지 않는다.
- PC가 꺼져 있을 때 수신되어 종이로 출력된 팩스는 이후 PC를 켜도 자동 저장되지 않는다.
- Easy Printer Manager의 NAS 경로 직접 지정 가능 여부도 미검증이다.
- 수신 담당 PC는 켜져 있어야 하며 절전·로그인 상태 및 프로그램 자동 실행 조건도 실제 확인한다.

## 업무 PC에서 이어갈 순서

1. NAS 제조사·모델명, 공유폴더 경로, 담당 PC 및 Windows 버전을 확인한다. 비밀번호는 대화에 받지 않고 사용자가 해당 PC에서 입력한다.
2. 복합기의 기존 전화선은 유지하고 사내 네트워크 연결 상태와 IP를 확인한다.
3. 모델·OS에 맞는 드라이버와 Samsung Easy Printer Manager를 설치하고 복합기 인식을 확인한다.
4. PC 팩스 수신, PDF 저장 위치, 수신 팩스 인쇄 옵션을 설정한다.
5. 환자 정보 없는 시험 팩스로 출력·파일 저장·여러 페이지 수신을 확인한다.
6. NAS 폴더 접근 권한과 파일 쓰기를 확인하고 자동 복사 방식을 설정·검증한다.
7. 이후 CRM 수신 자료함과 AI 처리 설계를 진행한다. 환자 연결과 AI 추출 결과는 직원 확인 후 반영하는 방향이다.

다른 PC에서 이어갈 때 이 문서를 먼저 읽고 실제 확인된 설정을 추가한다.


## CRM 쪽 구현 (2026-09-17, `fax_inbox.py` · `views/documents.py`)

현장(복합기·PC·NAS 폴더) 설정과 무관하게 CRM 쪽은 만들어져 있다. 계약은 하나 — **NAS 폴더에 PDF가 떨어진다.**

```
복합기 → 수신 PC(Easy Printer Manager, PDF 저장) → NAS 공유폴더(FAX_INBOX_DIR)
  → fax_inbox 워커(60초)가 새 파일 감지(해시로 중복 제외, 15초 안 된 파일은 복사 중으로 보고 대기)
  → Claude가 PDF를 읽어 환자 이름·주병명·보낸 곳·핵심 요약 (llm.analyze_document, 구조화 출력)
  → FAX_ARCHIVE_DIR/YYYY-MM-DD_이름_주병명.pdf 로 이동 (못 읽으면 날짜_미확인_원본명)
  → patient_documents(source=팩스) + communications(채널 팩스) → 대시보드 미처리 인바운드 카드 · 알림
  → /documents 자료함: 원본(PDF 뷰어) · AI 요약 · 판독값 수정→파일명 재정리 · 기존 환자 연결 · 상담 등록(이름·병명·모병원 prefill)
```

- 파일은 절대 지우지 않는다(이동만). 자료함 '삭제'는 CRM 기록만 지운다.
- AI 실패는 3회까지 다음 주기에 재시도, 그 뒤엔 화면의 [다시 판독].
- AI 판독은 **팩스 문서 자체(환자 식별정보 포함)를 Claude API로 보낸다.** 병원 방침상 안 되면 `FAX_AI_ENABLED=0` — 그래도 감지·자료함·원본 보기·수동 연결은 된다.
- `.tif`로 저장되면 자동 판독이 안 된다 → Easy Printer Manager에서 **PDF** 저장으로 설정.
- 권한: 상담 메뉴 조회=열람, 수정=판독·연결·완료·업로드. 감사 로그 `*_document`.
- **장수 제한**: 보통 팩스는 10~20장이라 `FAX_AI_MAX_PAGES`(기본 50, 2026-09-18 사용자 결정)면 통째로 읽고, 책 두께(수백 장)로 오면 앞 50쪽만 보낸다.
  환자·진단·의뢰 사유는 앞장에 있고, 검사지·투약기록을 다 보내면 시간(쪽당 1~3초)과 비용만 커진다. 크기 한도(25MB)는 자른 뒤 분량에
  적용되므로 두꺼운 팩스도 앞부분은 판독된다. 상세 화면에 "총 N쪽 중 앞 M쪽만 판독" 표시. 파일 자체는 통째로 보관.
- **보관기간**: `FAX_KEEP_DAYS`(기본 **10일**, 2026-09-17 사용자 결정)가 지나면 매일 `FAX_RETENTION_HOUR`(04시)에 **원본 파일만** 삭제하고 판독값·AI 요약·
  환자 연결은 DB에 남긴다(상세 화면에 '원본 삭제됨' 표시, 타임라인 유지). 수신·정리 폴더 밖 경로는 절대 지우지 않는다.
  근거: 팩스는 모병원 의무기록 **사본**이고 자료함은 상담 참고용이다. 정식 보존은 원본을 가진 모병원과 우리 EMR/의무기록실 몫 —
  입원한 환자의 서류가 진료에 필요하면 자료함 원본이 지워지기 전에 EMR 쪽에 붙여야 한다(의료법 보존기간은 그쪽 기록에 적용).
- 회귀: `tests/test_fax_inbox.py`(실제 API 호출 없음, 판독은 가짜 결과로 대체).

### 현장에서 확인할 것 (7단계에 추가)

1. NAS 공유폴더 이름·경로를 정하고 `docker-compose.yml`의 `/volume1/<공유폴더>:/fax` 주석을 푼다.
2. NAS `.env`에 `FAX_INBOX_DIR=/fax/수신`(수신 PC가 저장하는 하위 폴더 그대로) 추가 후 재배포.
3. 환자 정보 없는 시험 팩스 1장 → 60초 안에 대시보드 인바운드 카드에 '팩스 · …'가 뜨고 `/documents`에서 원본이 열리는지.
4. 정리 폴더에 `날짜_이름_주병명.pdf`로 옮겨졌는지, 수신 폴더는 비었는지(컨테이너가 공유폴더에 쓰기 권한이 있어야 한다).
5. 같은 팩스를 다시 넣었을 때 두 번 등록되지 않는지.
