# 모드 A — CRM 화면 (기존 CSS 수정)

**회귀 위험이 높다.** 아래 순서를 건너뛰지 않는다.

1. ⚠ **클래스를 쓰기 전에 존재를 확인한다**
   ```
   grep -n "\.클래스명" static/css/*.css
   ```
   없으면 **정의부터 만든다.** 없는 클래스를 써서 아무 효과가 없었던 사고가 반복됐다
   (`nowrap`, 작은 글자·버튼 클래스). "있겠지" 하고 넘어가지 않는다.

2. ⚠ **셀렉터가 걸리는 템플릿을 전부 센다**
   ```
   grep -rln "클래스명" templates/
   ```
   의도한 화면 하나만 바뀌는지 확인하고, 결과를 보고에 적는다.
   범례를 옆 카드에 잘못 넣은 사고가 있었다.

3. **기준 폭은 1440×850.** 1920만 보고 판단하지 않는다. 가로 스크롤은 실패로 본다.

3-1. ⚠ **표를 고쳤으면 렌더해서 눈으로 본다 — 짐작하지 않는다.**
   `table-layout:fixed` + `overflow:hidden;text-overflow:ellipsis` 인 표가 많아서,
   폭이 모자라면 **에러 없이 조용히 잘린다.** 코드로는 안 보인다. 반드시:
   ```
   python tools/render_png.py <저장한 html> out.png --width 1440 --scale 1
   ```
   실제 데이터(운영 백업 사본)로 렌더해 Read 로 그림을 확인한다. 샘플 한 줄로는 안 드러난다.

3-2. ⚠ **잘림은 "폭을 늘린다"가 아니라 "어느 열에서 덜어 오나"로 푼다.**
   고정 레이아웃이라 총합은 카드 폭에 묶여 있다. 늘리려면 반드시 어디선가 뺀다.
   판단 기준 — **사람이 훑어 읽는 값(구분·환자·주상병·날짜)이 먼저**고,
   **어차피 …으로 잘리고 툴팁에 전문이 있는 설명성 열(내용·메모·비고)이 양보한다.**
   넓은 열이 전부 `…` 이면 그 폭은 정보가 0이다.

3-3. **한 줄에 두 값을 넣지 말고 아랫줄로 쪼갠다.**
   `이름 + 성별/나이` 처럼 붙여 놓으면 좁은 칸에서 둘 다 잘린다.
   `<a>` 를 block 으로 깔고 부가값을 작은 글씨 아랫줄에 — 입·퇴원 현황 표가 쓰는 방식이다.
   한글 값은 `word-break: keep-all` 을 같이 준다('뇌졸중 기타'가 낱자로 갈라지지 않게).

3-4. **잘릴 수 있는 칸에는 `title` 을 반드시 붙인다.** 잘려도 마우스를 올리면 읽힌다.
   이미 잘리고 있던 칸을 발견하면, 폭을 못 늘리더라도 title 은 그 자리에서 채운다.

4. 파일 역할을 지킨다 — `dashboard.css`는 대시보드 전용, 전역은 `style.css`,
   기관협력은 `partners.css`. 전용 파일에 전역 규칙을 넣지 않는다.

5. 자동 갱신 페이지(`data-autorefresh`)의 본문 스크립트는 IIFE·함수 선언만 두고
   `window` 이벤트는 대입형(`window.onresize=`)으로 — 부분 갱신 시 중복 등록을 막는다.

# 모드 B — 이미지 (포스터·배너·표지·카드)

**CRM에 영향을 주지 않는다.**

- ⚠ `static/css/` 의 파일을 **절대 건드리지 않는다.** 이미지용 CSS는 그 HTML 안에 쓴다.
- 산출물은 `docs/design/` 아래에 둔다. `static/` 에 넣지 않는다.
- HTML+CSS+SVG로 만들고 PNG로 뽑는다:
  ```
  python tools/render_png.py docs/design/x.html docs/design/x.png --width 1200 --scale 2
  ```
- ⚠ **폰트를 반드시 명시한다.** 이 저장소는 Pretendard 파일을 싣고 있지 않아
  PC에 없으면 맑은 고딕으로 떨어진다. HTML 안에 `@font-face` 로 웹폰트를 넣거나
  `Malgun Gothic` 을 지정한다. 안 그러면 PC마다 글자가 달라진다.
- 이미지 생성은 **개발 PC에서만.** NAS 컨테이너에는 브라우저가 없다.

# 공통 절대 규칙

- 백엔드 로직·DB·라우트를 고치지 않는다. 고쳐야 할 게 보이면 **보고만** 한다.
- 환자 실명·연락처를 예시 데이터로 쓰지 않는다. 의료법 위반 표현을 넣지 않는다.
- 같은 실수를 두 번 하면 이 파일의 규칙에 한 줄 추가한다.

# 끝낼 때

작업 파일의 `## ③ 화면` 절**만** 채운다. 네 줄을 반드시 적는다:

```
바꾼 셀렉터   :
걸리는 템플릿 :  (grep 결과)
확인한 폭     :  1440×850  (렌더해서 그림으로 봤는지)
잘린 칸       :  없음 / 있으면 어느 칸·어떻게 처리했나
```

**표를 건드린 작업이면 `잘린 칸` 을 빈칸으로 두지 않는다.** 렌더한 그림에서 열을 하나씩
훑어 `…` 로 끝나는 칸이 있는지 보고 적는다. 고치지 못했으면 그렇게 적는다 —
"안 봤다"와 "봤는데 남겨뒀다"는 다르다.

# 고친 뒤 한 번 더

내가 고친 화면만 보고 끝내지 않는다. **같은 표 매크로·같은 클래스를 쓰는 다른 화면**이
있으면 그쪽도 렌더해 본다(2번의 grep 결과가 그 목록이다). 폭을 줄인 열이 다른 화면에서는
원래 딱 맞았을 수 있다.
